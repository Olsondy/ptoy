# 云端应用与本地模型共存部署

状态：accepted（方案与部署交付物已完成，尚未部署） · 2026-10-24

应用部署到 Ubuntu 云服务器，模型继续运行在本地 Windows，两端通过 Tailscale 连接。当前香港服务器只是临时承载实例，其 LiteSpeed 与 PHP 应用接入时必须保留；这些既有服务不是通用部署前提。本方案单独维护，不替换原有本地部署文档。详细设计见 [云部署方案](../architecture/cloud-local-models.md)。

执行入口为 [deploy/cloud](../../deploy/cloud/README.md)，包含配置生成、systemd、排空发布、独立 Caddy 配置与已有 LiteSpeed 的接入模板。应用脚本已完成本地 Linux 隔离验证；未操作公网服务器，入口、媒体与容量仍需现场验收。

## 已确认的边界与取舍

- 云端负责网页、访问控制、LiveKit 与 Voice Agent；模型及 TTS 参考资源留在本地，不迁移模型。访问控制遵循 ADR 0010。
- 模型离线时保留网页及邀请验证，通话不可用；不排队、不自动唤醒本机、不切换付费云模型。接受家庭主机可用性决定语音能力的限制。
- 发布允许维护时段，停止新通话并等待既有通话结束；不建设无停机集群。已有其他应用时保留其服务。
- 本期不做备份或灾难恢复，不引入对象存储。此范围取代此前的每日备份建议；保留 SQLite 持久化与正常重启后的占用对账。

## 架构选择

- Web 入口可替换：已有 LiteSpeed、Nginx、Apache 等服务时复用其 HTTPS/WebSocket 入口；没有时使用 Caddy。当前临时服务器沿用 LiteSpeed/PHP，新服务器无需为了本应用安装 LiteSpeed。
- 两种接法遵循同一契约：静态网页、同源 `/api/` 代理、独立 RTC 域名的 HTTP/WebSocket 代理，内部授权接口不公开。直接开放 LiveKit 媒体端口，首期不提供 TURN/TLS 443；接受部分受限网络无法通话。
- 采用独立 systemd 服务及发布目录；安装、更新脚本与 Web 服务选择解耦。入口配置由操作者显式应用，不自动替换已有服务或抢占其端口。

## 替代方案与影响

强制所有机器安装 LiteSpeed 会将临时环境变成应用依赖；已有入口时整体替换也会扩大对其他站点的影响。因此保留通用服务部署，只按机器现状选择入口。第二公网 IP 或四层 SNI 分流可另行实现 TURN/TLS 443 回退，但会增加费用或入口运维复杂度，取决于用户是否需要受限网络覆盖。

选择最小可用的单机共存方案，不增加备份、灾难恢复或无停机发布设施；不再约定恢复时间或最多丢失 24 小时变更的目标。本决策不会禁用正常进程重启和邀请码状态持久化。

2 核 4 GiB 为临时服务器的现有资源，不是强制规格，也不构成 3–5 路并发的承诺；Agent VAD、本地模型排队以及同机其他应用负载都需实测。实际服务器版本、端口监听、域名与 Tailscale 链路是部署前核验项，不能以草案代替检查结果。
