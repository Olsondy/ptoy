# 邀请访问控制与每码单通话

状态：accepted（已本地实现并完成本轮验证；未部署） · 2026-10-24

ptoy 面向维护者和少量受邀朋友，需要按人发放、重复使用和单独撤销访问资格。采用每人独立邀请码，验证后获得固定 30 天的浏览器访问会话；同一码允许多设备验证，但同时只能拨打或维持一通电话。邀请控制访问资格，角色链接只选择角色，两者分离。

## 已确认的决策及原因

以下规则经两轮审查确认，后续技术方案必须满足，不能以实现方便为由改变。

| 决策 | 明确行为与取舍 |
|---|---|
| 每人一个可复用邀请码 | 长期有效直到维护者撤销；换设备可以输入原码。无需注册账号，也不能据此证明使用者就是收码本人。 |
| 授权全部可选角色 | 主页可切换，固定角色链接打开后不能切换；分享角色链接不转移访问资格。 |
| 固定 30 天会话 | 从每次验证成功起计时，普通访问不续期。已建立的通话遇到会话到期可以聊完，下次通话前重新验证。 |
| 多设备验证、同码一通 | 从服务端允许拨号起占用名额；连接中也计入。其他设备提示“此邀请码正在通话，请结束后重试”，不抢占、不排队。 |
| 结束与重连 | 取消、拨号失败或通话结束后释放；短暂断线重连保留原占用。异常退出不能永久占用，也不能误放行第二通。 |
| 撤销邀请 | 所有关联设备不得继续访问受保护功能或开始新通话；连接中的尝试终止，已经建立的通话允许结束。 |
| 先验证再进入 | 主页与固定角色页都先验证，成功后返回原目标。未验证不加载角色、不申请麦克风、不创建房间。始终手动开始通话。 |
| 退出此设备 | 只结束当前浏览器会话，其他设备不受影响；当前通话先挂断再退出。提供低干扰入口。 |
| 服务器命令管理 | 维护者通过命令创建、列出、撤销邀请；本期不做管理后台、公开注册、账号恢复或付费。 |
| 本期资源控制范围 | 只限制同码一通，不增加全局并发上限、每日额度、通话时长上限或排队。实际承载能力另行压测。 |

邀请码允许转交，单通话限制只能阻止同码同时使用，不能阻止轮流使用。选择这种边界，是为了保持朋友使用时的简单流程，而不是引入实名、设备绑定或完整账号体系。

## 技术决策与取舍

### 1. 单机持久存储与服务端会话

由现有 Token 服务管理邀请、浏览器会话及通话占用，使用服务器本机 SQLite 持久化；网页与 API 经同源 HTTPS 提供。适合当前单台应用服务器，不增加独立数据库或 Redis。多实例横向扩展时需要重新审查存储与并发协调方式。

- 邀请码使用密码学安全随机数生成，只保存规范化后的摘要；明文创建时显示一次，不放入 URL 或日志。丢失时撤销旧码并重新发放。
- 浏览器持有随机的、不含业务资料的会话凭据，通过 `HttpOnly; Secure; SameSite=Lax; Path=/` Cookie 传递；服务端保存摘要、邀请关联和到期时间。
- 每次受保护请求检查会话与邀请状态；不能只相信前端状态或一张长期不查状态的 JWT。
- 邀请管理命令访问同一持久数据；撤销与拨号准入在同一事务边界内判断。数据库正常重启不丢失。按 ADR 0011 的最新部署范围，本期不建设备份或灾难恢复。
- 写接口校验来源及请求格式；验证入口按可信来源 IP 和邀请码摘要限流。随机码长度、驱动版本和限流阈值在实施规格中确定。

代价是 Token 服务由无状态签发器变为有状态访问控制服务，需要维护数据库与恢复流程。浏览器会话存在服务端，换来了可单独退出和跨设备撤销的确定行为。

### 2. 用服务端准入界定“已经建立”

将“已建立”定义为：Agent 确认对应参与者的媒体连接已就绪，并在启动通话 pipeline 前，向访问控制服务完成一次原子的准入确认。网页收到确认后才显示可通话；拿到 LiveKit token、连上信令或单纯进入房间都不等同于已建立。

准入确认与撤销串行裁决：撤销先成功，连接中的尝试不能启动模型；准入先成功，则属于可正常结束的既有通话。会话到期和取消也在准入时检查。准入后短暂重连沿用同一个通话标识，不获得新的通话资格。

这样将授权边界放在应用掌控的服务端，而不是依赖浏览器状态或 LiveKit token 的剩余有效期。Agent 只接受可信内部调用和服务端存储中的邀请、尝试、房间及参与者绑定，不能信任浏览器自行填写的授权属性。

官方文档明确：自建 LiveKit 移除参与者或更新权限不会撤销旧 token；到期不终止现有连接，连接期间还可能刷新凭证。因此，**缩短 token 有效期不等同于撤销凭证**。[官方凭证说明](https://docs.livekit.io/frontends/reference/tokens-grants/)

本决策接受以下边界：已取消或被撤销阻止的尝试不能启动模型或恢复有效通话，但持有旧凭证仍可能连接空房间，不保证禁止入房本身。准入先完成的既有通话可以继续，即使模型实际启动发生在随后撤销之后；裁决以服务端准入事务为准。部署版本的重入、就绪和重连行为仍需专项验证，token TTL 在实施规格中确定。

### 3. 持久占用、事件处理与异常对账

每个邀请在服务端最多有一个未结束的通话尝试，用事务保证多设备同时拨号只成功一个。请求重试关联同一个尝试，不能重复占用或创建新通话。占用至少区分：连接中、已建立、结束；重连属于原通话的延续。

取消或失败须先使旧尝试不可再次准入，再释放名额。保留足够的结束记录拒绝迟到 token、旧请求和旧 Agent；重复或迟到的结束事件不能释放新的通话占用。客户端通知可加速回收，不能作为唯一依据。

结合服务端事件、Agent 状态及 LiveKit 房间/参与者查询对账。未入房、响应丢失、Agent 启动失败和进程重启都要可恢复；不依赖单个 webhook 必达，也不直接因为一个计时器到期就允许第二通。

官方 webhook 不保证送达；`participant_joined` 对应媒体连接已建立，而 SDK 的 `ParticipantConnected` 可以更早发生。当前 `agent.ts` 使用的 `waitForParticipant()` 不能单独作为媒体已就绪的证明。准入前应核实就绪状态；收到事件和主动查询的处理须保持幂等。[官方事件说明](https://docs.livekit.io/intro/basics/rooms-participants-tracks/webhooks-events/)

状态无法确认时暂时拒绝新拨号并提示稍后重试；恢复后自动核实并释放已结束的占用。它优先保证同码一通，接受控制服务或 LiveKit 故障时暂时不能新拨号的代价。具体等待时间和对账周期需实测确定，不构成通话时长上限。

## 接口与部署边界

架构位置与部署事实以 [server.md](../architecture/server.md#9-运维注意) 为准。正式实现时需要覆盖以下职责，具体请求字段另写实施规格：

| 边界 | 职责 |
|---|---|
| 验证及会话接口 | 验证邀请码、恢复浏览器资格、退出当前会话；验证错误、撤销、限流及网络异常可区分处理。 |
| 角色列表与角色链接接口 | 必须验证访问资格；固定链接继续单独校验角色。 |
| 通话凭证接口 | 验证会话和角色，原子申请通话占用，再签发绑定本次尝试的凭证；禁止绕过占用直接签发。 |
| Agent 内部准入与结束接口 | 身份验证、原子准入、关联正确的尝试、幂等处理结束；不能暴露为浏览器可自报授权的接口。 |
| 健康检查 | 仅暴露最小健康状态，不返回邀请或角色资料。 |

模型接口网络保护属于部署边界；页面邀请码本身不会改变模型服务的网络可达性。新授权检查失败时不得跳过鉴权。已有通话不因浏览器会话自然到期或邀请撤销被主动中止。

## 被放弃的方案

- **共享密码或共享 Basic Auth**：部署简单，但不能单独撤销某位朋友，也不匹配当前浏览器会话的退出体验。
- **一次性兑换码或完整账号体系**：前者换设备不便，后者带来密码恢复、资料及管理成本，均不符合可复用、少量朋友使用的目标。
- **只加页面输入框或依赖加密角色链接**：可以直接绕过页面申请通话凭证，无法形成访问控制。
- **仅签发时鉴权、只靠短 token 或 webhook 回收**：无法完整处理撤销竞态、已发未用凭证、事件缺失和异常退出。

## 验收边界与后续切片

产品规则与技术取舍已经确认，规格与实施任务见 GitHub #32–#35。正式前后端已本地接入邀请访问控制，尚未部署；以下仍作为验收要求。

1. **邀请与会话**：创建、查询、撤销；重启后数据保留；大小写和分隔符规范化；30 天不自动续期；多设备验证与单设备退出；直接请求受保护接口必须鉴权。
2. **占用与准入**：同码多设备/多标签页竞态只准入一通；申请 token 后、准入前发生撤销、取消或到期不能启动模型；准入先完成则撤销或会话到期不打断既有通话；两种先后顺序均可重复验证；旧凭证入房不能绕过准入，迟到回调不影响下一通。
3. **异常恢复**：响应丢失、未入房、拨号失败、浏览器关闭、短暂重连、最终断开、Agent/API 重启、重复或缺失事件；不会永久卡住，也不会放行两通。
4. **页面与真实链路**：验证后保持原角色 URL；错误保留可重试输入；手机与键盘操作；受保护访问失效后回到入口，已有通话聊完再返回；正式通话、字幕开关、隐藏字幕时的错误提示与角色菜单保持可用。

## 原型与当前差距

正式实现已完成本轮验证：36 项后端测试（包含云端维护/模型就绪）、原有 11 项真实 LiveKit/Chrome 端到端测试、1 项真实信令恢复测试和 4 项部署可用性浏览器用例，以及类型检查、生产构建和 CLI 跨进程持久化验证。独立代码审查未发现确认的阻塞缺陷。原本地部署文档保持原样，邀请码实施状态以本记录为准。

隔离的真实 LiveKit/echo 故障验证已覆盖：API 硬退出后重开、Agent 进程树硬杀、成功准入响应丢失、慢清理，以及慢清理叠加 API 中断。验证中修复了慢清理停止心跳造成过早回收的问题，并增加 API 重启后的续约窗口。信令恢复测试观察到真实 ICE restart，同一通话恢复且其他设备保持 busy。

验证使用合成角色和本机 LiveKit，不读取真实角色文件；不等于公网 UDP/TURN、长期网络分区或云端模型容量已验收。故障验证入口为 Agent 的 `check:access-recovery` 命令，浏览器测试使用独立的 echo 环境。

独立原型已统一归档至 [resources/prototypes](../../resources/prototypes/README.md)：[邀请码原型](../../resources/prototypes/invite.html)与[年龄确认原型](../../resources/prototypes/invite-age.html)均可直接用浏览器打开，不需要启动 Vite。演示码为 `7K2M-9Q4R-X6WP-3T8N`，只用于本地演示。

原型使用独立 localStorage 数据模拟验证和 30 天记忆，不访问 API、麦克风或模型；审查面板不属于正式产品。它已演示撤销/到期不打断模拟通话，尚未覆盖多设备占用、真实连接中的撤销、服务端准入、异常恢复及退出此设备。原型不能作为这些能力已完成的证据。

## 决策状态与实施参数

2026-10-24 完成三轮审查，产品规则与上述技术取舍全部接受，无待确认的架构决策。数据库驱动、随机码长度、限流阈值、token TTL、对账周期及恢复等待时间由实施规格和验证确定；这些参数不得改变已确认的访问、撤销及单通话语义。若实施验证发现无法满足本决策，应明确修订 ADR，不得静默放宽验收。
